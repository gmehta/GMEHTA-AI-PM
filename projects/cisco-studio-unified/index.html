PM thesis. One Studio, four surfaces — Assistant, Canvas, App Builder, Agent Builder — held together by one shared Block Library. Each surface is a projection of the same Data / Skills / Actions / Surfaces blocks. Build once, surface everywhere.
Assistant
The universal entry. Describe intent in plain language — Studio assembles it from your shared blocks, then you choose how to surface it.
Why Assistant is the front door: one natural-language entry that can query, compose, or launch any surface. The same intent can become an app view, an agent, or an Assistant skill — because they're all the same blocks underneath.

Edge #1 — Actions are a first-class, governed block. In Cisco's current UI, "do not make changes" is a sentence in the prompt. Here, a write-action is its own block with an explicit scope + HITL gate — so governance binds to the operation, not the instruction.

Block Library the shared substance
Build a block once; reuse it across every surface. The "used in" tags prove the unification — the same blocks power the app, the agent, Canvas, and the Assistant.
This is the whole thesis in one screen. Studio is small because the Library is shared. Notice Data blocks are reused most (everything needs them); Actions carry governance badges; Surfaces are the most bespoke. The Library is the moat — apps and agents are just compositions.
Marketplace
Certified Cisco + partner blocks, agents, and apps — deploy in one click, governed on arrival.
Skills travel; agents are turnkey. Publishing reusable blocks (esp. skills) compounds the Library; a purchased skill runs inside the buyer's own governed agent — sidestepping the "trust a stranger's agent" barrier.
